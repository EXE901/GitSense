==============================================================
GitSense — SEO, Indexing & Discoverability Implementation Report
==============================================================

OBJECTIVE
---------
Implement production-grade SEO foundations:
  • robots.txt
  • sitemap.xml
  • improved root metadata (OpenGraph / Twitter / canonical)
  • structured JSON-LD data
  • per-route metadata hygiene
without redesigning the frontend, changing branding, or
introducing tracking vendors / SEO libraries.

==============================================================
ROBOTS.TXT STRATEGY
==============================================================
Generated by Next.js at /robots.txt. Production output:

  User-Agent: *
  Allow: /
  Disallow: /dashboard
  Disallow: /dashboard/
  Disallow: /activity
  Disallow: /activity/
  Disallow: /analytics
  Disallow: /analytics/
  Disallow: /issues
  Disallow: /issues/
  Disallow: /repositories
  Disallow: /repositories/
  Disallow: /trends
  Disallow: /trends/
  Disallow: /settings
  Disallow: /settings/
  Disallow: /auth/
  Disallow: /api/

  Host: https://gitsense.tech
  Sitemap: https://gitsense.tech/sitemap.xml

Rationale:
  • Public landing + auth entry points (login/signup) remain
    crawlable — these are legitimate marketing surfaces.
  • Private workspace surfaces (dashboard/analytics/etc.) are
    explicitly disallowed; they require auth, return empty
    HTML to crawlers, and shouldn't compete with the landing
    page for SERP impressions.
  • OAuth callback path disallowed.
  • Sitemap + Host hints provided to Google.

==============================================================
SITEMAP.XML STRATEGY
==============================================================
Generated dynamically by Next.js at /sitemap.xml. Indexed URLs:

  /                  priority 1.0   weekly
  /login             priority 0.6   monthly
  /signup            priority 0.6   monthly
  /forgot-password   priority 0.3   yearly

URLs are absolute, HTTPS, canonical (no trailing slashes
except root). Private routes are excluded (they're already
disallowed in robots.txt and noindex'd at the layout level).
Sitemap is regenerated on every build — lastModified reflects
the deployment time.

METADATA IMPROVEMENTS
==============================================================
Title:
  • template: "%s · GitSense" — per-page short titles compose
    into branded SERP entries.
  • default: "GitSense — Engineering Intelligence for GitHub
    Workspaces" (unchanged tone, preserves visual identity).

Description:
  • Promoted to shared constant.
  • Operationally accurate, developer-tooling-oriented copy.
  • No fake metrics or marketing fluff.

Keywords:
  • Expanded but factual:
    GitHub analytics, GitHub issue tracking, engineering
    analytics, DevOps dashboard, developer productivity,
    workspace health, operational insights, issue
    intelligence, contributor analytics, backlog pressure,
    GitHub workspace, engineering metrics.

Canonical URLs:
  • Root layout: alternates.canonical = '/'
  • Each public page: alternates.canonical = '/<route>'
  • metadataBase = SITE_URL → resolved against
    https://gitsense.tech in production, http://localhost:3000
    in dev. No localhost leakage in prod builds.

Robots directives:
  • Default: index: true, follow: true
  • googleBot: max-image-preview: large, max-snippet: -1,
    max-video-preview: -1 — enables rich image previews
    and full-snippet rendering in Google SERP.

==============================================================
STRUCTURED DATA (JSON-LD)
==============================================================
Injected on the landing page only as application/ld+json.
@graph contains three nodes with stable @id values:

  • Organization (@id: /#organization)
      - name, url, logo, sameAs (GitHub repo)
  • WebSite (@id: /#website)
      - name, url, description, publisher → Organization
      - inLanguage: en-US
  • SoftwareApplication (@id: /#software)
      - applicationCategory: DeveloperApplication
      - operatingSystem: Web
      - offers: free (price 0 USD)
      - author/publisher → Organization
      - image → absolute OG image URL

Deliberate omissions (per instructions — no fake metrics):
  • No aggregateRating
  • No reviewCount
  • No userInteractionCount
  • No fabricated install counts

==============================================================
CANONICAL URL STRATEGY
==============================================================
  • Single SITE_URL constant in lib/seo.ts, sourced from
    NEXT_PUBLIC_SITE_URL with a production fallback of
    https://gitsense.tech.
  • Trailing slash stripped defensively.
  • metadataBase ensures all relative paths (icons, OG
    images) resolve absolutely in production.
  • Each public page declares its own canonical alternate.
  • No duplicate canonicals — title.template composes
    per-page titles without overriding root canonical.

==============================================================
REMAINING SEO LIMITATIONS
==============================================================
  • No dedicated 1200×630 OG image — currently reuses the
    product logo PNG. A purpose-designed OG card image
    would improve preview density on Discord/Twitter/X but
    is a design asset task, not an engineering one.
  • No blog/docs surface yet — sitemap is intentionally
    small. As marketing content is added, extend
    src/app/sitemap.ts.
  • No Google Search Console verification meta tag — add
    via metadata.verification once a Search Console
    property is provisioned.
  • No hreflang alternates — site is currently en-US only.
  • Twitter handle (@gitsense) is a placeholder; update in
    src/lib/seo.ts if a different handle is owned.
  • No RSS / Atom feed (no content surface yet).
